# LangGraph Orchestration

The workflow is implemented in `backend/app/graph/workflow.py`. Callers must
provide a router, each pipeline stage, the deterministic verifier, an explainer,
an audit recorder, and a checkpointer; the graph does not silently substitute
fake implementations.

## Routes and nodes

- `route` maps the intent router's supported intents to `full_analysis`,
  `retrieval_only`, or `out_of_scope`.
- `full_analysis` runs `redact` → `extract` → `enrich` → `forecast` →
  `retrieve` → `verify` → `decide` → `hitl_wait`.
- `retrieval_only` runs `retrieve` and skips compliance scoring.
- `out_of_scope` skips pipeline stages and goes directly to explanation.
- All routes finish with `explain_publish` → `record`.

Stage adapters can update only their designated state fields. Full analysis
requires claims and a verification context. The verifier's verdicts and the
decision node's scorecard are deterministic; an LLM explainer receives only
the final status, reason codes, claim/rule IDs, evidence IDs, and risk score.
It receives no query, document text, or evidence payload and cannot alter the
scorecard or verdicts.

## Risk and escalation

`config/graph.yaml` sets three ordered thresholds:

- `0.85`: recommend a re-audit.
- `0.90`: escalate to human review with normal priority.
- `0.95`: escalate to human review with critical priority.

An escalation generated by the verifier is preserved. Any escalation causes
the final status to be `review_required`; absent escalation, a failing verdict
produces `non_compliant`, otherwise the status is `compliant`. Retrieval-only
and out-of-scope workflows have an informational explanation and no scorecard.

## Retries and execution limits

`max_node_attempts` caps stage/retry attempts, and `recursion_limit` is passed to
LangGraph on invocation and resume. Automatic retry is limited to explicitly
transient `RetryableWorkflowError`, `ConnectionError`, and `TimeoutError`.
Programming, validation, and other deterministic errors are not retried.

## Human review and checkpointing

An escalated run pauses at `hitl_wait` with a LangGraph interrupt. Resume it with
the same `thread_id` and a validated `ReviewDecision` (`approved`, `rejected`,
or `more_evidence`). Durable restart/resume requires a PostgreSQL checkpointer:
start the local Compose services and use the `TEST_DATABASE_URL` in `.env`
(or set `ECOCHAIN_TEST_POSTGRES_URL` to the same local test database), then run:

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\integration\test_graph_postgres_resume.py -q
```

The integration tests launch a child process that pauses at HITL, terminate it,
restart the PostgreSQL container, and resume the same thread in a new process.
They verify the final scorecard, persisted audit row, and audit hash chain; a
second test runs all 150 golden cases through PostgreSQL-backed workflows.
Without either database URL setting, both tests are skipped. In-memory workflow
tests do not establish durable restart behavior.
