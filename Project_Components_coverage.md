# EcoChain Copilot: Project Components Coverage

## 1. The problem

Brands must prove their factories are ethical and sustainable, but compliance officers manually read thousands of messy scanned PDFs (certificates, invoices, BOMs, audit reports). It is slow, inconsistent, and discovers risk only after orders are placed. See `problem_statement.md` for the regulatory context (CSDDD as amended by Omnibus I).

## 2. The solution

A manager uploads a batch of supplier documents. A team of agents redacts sensitive data locally, extracts structured fields, retrieves the applicable law, verifies each claim with deterministic rules, forecasts the factory's six-month failure risk, and produces an audit-ready scorecard. Uncertain or failing cases pause for a human reviewer, and the reviewer's decision is logged.

Design principle: language models explain, deterministic code decides.

## 3. The agents and components

Each has one responsibility and communicates only through typed LangGraph state.

| Component | Role | Decides? |
|---|---|---|
| **Orchestrator** | Routes requests, enforces step budgets, applies escalation rules, reads the risk forecast to adjust thresholds, and drives the final "explain and publish" step (the LLM drafts explanations from verified results only and the scorecard is rendered) | Routing and escalation (rule-based) |
| **Redaction Agent (local)** | Local OCR and layout extraction, then two-pass PII and pricing redaction with reversible pseudonyms | No |
| **Document Extraction Agent** | Turns redacted documents into structured fields (certificate type, issuer, dates, scope, BOM lines) with page, bounding box, and confidence | No |
| **Compliance RAG Agent** | Hybrid BM25 + dense retrieval with reranking, filtered by jurisdiction and effective date; returns article-level citations and checks that each citation entails the claim | No |
| **Predictive Risk Agent** | PyTorch LSTM returns a calibrated six-month failure probability, used as a control signal | Supplies a signal |
| **Deterministic Verifier** | Rule-based checks returning pass, fail, or escalate per claim. It runs inside the privacy boundary on vault-mapped real values, not on pseudonyms, so issuer and facility matching work | **Yes** |

The report-writing step is not a separate agent: scorecard text is generated by the LLM only from Verifier verdicts and evidenced claims.

## 4. Technology summary

- **Frontend:** Next.js, TypeScript, Tailwind CSS, shadcn/ui, SSE for live agent progress, PDF viewer with bounding-box overlay.
- **Backend:** FastAPI, Pydantic, Redis with Celery or Arq (choose one) for background jobs, Postgres for application data, checkpoints, and the append-only audit log.
- **Orchestration:** LangGraph (typed state with append-only reducers, recursion limits, interrupt/resume by thread_id), LangChain for loaders and wrappers.
- **ML:** PyTorch LSTM with calibration against logistic regression and XGBoost baselines; TensorFlow/Keras intent router benchmarked against an embedding + logistic-regression baseline.
- **Generative AI:** a pinned, currently supported Gemini model behind a provider-agnostic interface, used on redacted text only; LayoutLMv3 plus local OCR (PaddleOCR or Tesseract) for extraction; Presidio and quantized Llama 3 for redaction.
- **Retrieval:** ChromaDB, Sentence-Transformers, BM25, cross-encoder reranker, versioned regulation metadata.
- **Evaluation and ops:** golden evaluation set, Ragas (judged by a different model family), extraction F1, Brier score and AUROC, CI gates, LangSmith, Docker.
